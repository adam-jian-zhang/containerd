containerd Architecture Overview

containerd Architecture Overview

Introduction

containerd is an industry-standard container runtime with an emphasis on simplicity, robustness, and portability. It is designed to be embedded into a larger system rather than being used directly by developers or end-users. containerd is a CNCF graduated project and serves as the container runtime for Kubernetes and other container orchestration platforms.

Version: v2.0+
Language: Go 1.24.3
License: Apache 2.0

High-Level Architecture

containerd follows a modular, plugin-based architecture that provides flexibility and extensibility. The system is composed of several key layers:

containerd API Layer

containerd API Layer

Overview

The API layer defines all external interfaces for interacting with containerd. It is implemented using Protocol Buffers (protobuf) and exposed via gRPC and TTRPC protocols. The API is versioned to maintain backward compatibility and stability.

containerd Plugins Architecture

containerd Plugins Architecture

Overview

containerd is built around a plugin-based architecture that allows extending functionality without modifying the core daemon. Plugins implement the interfaces defined in the core packages and are loaded dynamically at runtime.

Location: plugins/

Key Concepts

  • Content-Addressable Storage - All content identified by SHA256 digest with automatic deduplication
  • Layered Filesystems - Snapshots provide efficient copy-on-write semantics
  • Plugin Architecture - Modular design with easy extensibility
  • Smart Client Model - High-level operations in the client, daemon focuses on low-level operations
  • Daemonless Containers - Shim-based architecture allows containers to survive daemon restarts
  • Namespace Isolation - Multi-tenancy support with separate namespaces
  • Lease-Based Garbage Collection - Resource protection with automatic reference tracking
